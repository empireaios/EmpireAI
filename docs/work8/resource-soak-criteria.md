Scenario seeds1800–1919; 120 samples at5second intervals; measured elapsed minimum600seconds. Each executes actual joint commerce crash/recovery, unknown-supplier containment and financial-conflict denial, then reopens the canonical store and requires fresh fulfilment BLOCKED without receipt mutation. No provider access or inference. Kernel egress denial is mandatory.

Pass thresholds declared before execution: every scenario and invariant passes; exactly one permitted receipt/cursor repair per scenario; zero forbidden repair/effect/paid calls; p99 sample duration <=2000ms; peak RSS <=512MiB; growth from initial RSS <=128MiB; source hashes unchanged. Retain sample latency, memory, CPU, receipt digest and outcome. Any failure is NO-GO for this exam and requires targeted diagnosis rather than relaxed thresholds.

This extends the earlier120second pilot with measured resource and tail-latency evidence after stock/fulfilment changes. Each scenario uses a fresh store; it is not a sustained shared-volume workload, hosted deployment, real-source business lifecycle or whole-system graduation. Accelerated multi-day finance and portfolio runs remain separate evidence. No paid or hosted canary is required by this examination.

Run from repository root with Node22 and the available tsx loader through scripts/work8/isolated-exec.py: `node --import /absolute/tsx/dist/loader.mjs scripts/work8/resource-soak.mjs`. Output resource-soak.json records IN_PROGRESS or explicit PASS/FAIL; a partial file is not a pass.
