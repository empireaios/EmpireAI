# Work 8 simulated financial projection

`backend/src/runtime/commerce-runtime/governed/work8-finance.ts` is a pure derived projection over verified immutable governed-commerce history and explicitly simulated examination events. It does not create a financial database or write actual accounting records. API: `projectWork8Finance(store, workspace, missionId, events, cutoffAt)`. The projection itself reads and verifies the canonical store history, derives state internally and binds events to that receipt. Caller-supplied state or receipt hashes cannot substitute for this read. The orchestrator retains input events in examination evidence.

Each event identifies its source receipt, SANDBOX order, currency, event identity, timestamp and integer minor-unit amount. Conflicting retries, missing orders, foreign currency without conversion evidence, over-crediting suppliers, over-paying liabilities and drawing settlements/holds before funds exist fail closed. Exact retries are counted but not posted twice. Distinct currencies remain separate, and no currency precision or exchange rate is inferred. Category amounts must already be in the documented currency minor unit.

The replay includes sales, discounts, COGS, freight, duties, fees, refunds, chargebacks, supplier credits, settlements, payout holds/releases, bank receipts and supplier payments. Liabilities and negative bank positions expose simulated cash need. Unknown values and missing mandatory economics prevent contribution/realised contribution claims. Realisation also requires zero unsettled funds and supplier liability. Technology costs are explicitly separate.

The conservation oracle totals source categories independently of journal mapping and compares contribution to assets less liabilities. Journal balance alone is insufficient. Period cutoff excludes future events while retaining their IDs. All UI consumers must use SIMULATION_EXCLUDED_FROM_ACTUALS and null actual revenue/profit; actual cash movement is always zero.

Verification: five no-network local tests pass under Node 24.19.0, including 100 deterministic integer scenarios, full settlement/hold/release, negative cash, losses, duplicate/conflicting events, missing fee, cutoff and unsafe source/amount cases. This is component evidence, not Work 8 completion.

Outstanding integration/coverage: canonical orchestrator retention and API/UI exposure; explicit evidenced FX conversion with rounding journals; platform reserves beyond payout holds; bank/provider contract tests; durable crash-at-commit/replay examinations through the canonical store; full source-to-UI proof and exact production Node runtime validation. No external commercial effects or inference executed.

Independent-review correction: SALE must equal canonical selling price times order quantity; COGS equals canonical order line unit costs (checked against offer); FREIGHT equals canonical offer freight times quantity; refunds match canonical remedy totals and cannot be omitted while claiming complete economics. Duplicate SALE/COGS/FREIGHT/FEE/DUTY/DISCOUNT/REFUND aggregate categories are rejected even with different event IDs. Other financial inputs require explicit simulation assumption references and are labelled assumptions rather than source facts. Supported two-decimal currencies are explicit; other currency precisions fail closed. Eight finance/operating/joint tests passed after correction under exact Node 22.23.2 and kernel egress denial, including forged amounts and state/receipt pairs.
