# EmpireAI — Journey First Doctrine

**Canonical label:** Journey First Doctrine  
**Status:** ✅ Permanent repository governance rule  
**Registered:** BL-B Item 009 (2026-06-29)  
**Canonical owners:** Journey · Repository Governance · Pillow Architecture

---

## 1. Doctrine

The Journey is **not merely documentation**. The Journey is the **living operational map** of the Empire.

---

## 2. Synchronization rule

Every approved engineering, governance, architectural, or commercial change shall **first** determine:

> **Does the Journey require synchronization?**

Only after that evaluation may other repository owners be updated.

If the Journey changes, **all dependent repository owners** shall be synchronized accordingly.

---

## 3. Pillow obligation

Pillow shall **always** use the Journey to determine the Empire's current operational position **before** providing executive recommendations about EmpireAI.

---

## 4. Cursor obligation

Whenever Cursor receives an approved mission or governance update:

1. Evaluate Journey synchronization **first**.  
2. Update `JOURNEY.md` if required.  
3. Update `JOURNEY_AUDIT.md` with structural change log.  
4. Record Journey modifications in the Executive Audit.  

The Journey shall **never become stale**.
