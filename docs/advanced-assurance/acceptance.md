## Required production operating proof

- Owner-free recovery: eligible controlled operational fault, software detection, deterministic diagnosis, admitted allowlisted runbook, execution, verification of the original functional capability, immutable incident/attempt/verification receipts, owner page update. Manual Work repair is not autonomous recovery.
- Advisor: automatic task initiation without owner messaging ChatGPT; actual supported mechanism and execution identity; independent evidence read; authorized bounded action; durable authenticated writeback; independent Assurance outcome verification; incident closure. Separate API agent from interactive ChatGPT wake-up. A configured route or read-only MCP alone is not proof.
- Owner approval: persistent prominent alert, plain-English capability/impact/attempts/proposal/reason/consequences, exact scoped approval or rejection, automatic follow-through and functional verification, durable receipt. No decorative buttons, hidden human steps or repeated continue requests.
- Deployment collision: executable overlapping deployment/recovery test proves exclusive change owner, lease fencing, stale actor rejection, conflicting recovery deferral, preserved critical monitoring and constitutional safety, post-deployment reconciliation, no duplicate deployment or corruption.
- Assurance self-failure: independent supervision detects failed monitoring, truthful degraded/unknown state, durable incident, eligible automatic recovery or actionable owner escalation.
- Independence: observation/diagnosis/recovery/alerts persist without Pillow, Advisor or owner browser; degraded collector does not unnecessarily disable unrelated capabilities.
- Durability across ordinary runtime replacement: incidents, recovery jobs, Advisor tasks/results, communications, owner approvals, deployment leases, monitoring state and receipts. Preserve persistent-volume identity.
- Historical failure classes using non-paid fixtures: pricing expiry, inference admission, schema mismatch, Four Eyes commissioning, missing returned evidence, incomplete response persistence, Advisor retrieval, stale closure, post-inference handoff. Do not repeat Candidate #001 investigation.
- Incident learning: preserve original failure, root cause, attempts, verified remedy, recurrence signature, prevention and regression references.
- Security fixtures: unauthenticated action, forged/replayed Advisor task, malicious incident/prompt injection, expired grant, approval replay, cross-workspace access, unauthorized deploy, secrets and authority escalation.
- Financial discipline: bounded monitoring/retries; deduplicated accounted provider and Advisor calls; failed inference remains recorded; reservations/usage estimates distinct from actual settlement; no financial authority expansion or arbitrary tiny inference budget.
- Performance: evidence for practical overhead, detection/processing/recovery latency, queue/storage impact, owner responsiveness and invocation overhead. Do not invent measurements.
