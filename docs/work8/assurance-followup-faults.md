### Independent stock-delta review and cancellation regression

Reviewed `work8-stock.ts`, canonical engine intake, and actual two-connection stock race. The stock commitment read is inside the existing `BEGIN IMMEDIATE` command transaction and checks matching canonical histories. It counts all units except cancelled/rejected orders across missions for the same provider/product/variant/warehouse; delivered or refunded units are deliberately not replenished. This is conservative simulation capacity accounting, not proof of supplier inventory reservation.

A real regression was reproduced: after a timeout and one unconfirmed cancellation, a second distinct `confirmed:false` cancellation changed `RECONCILIATION_REQUIRED` to `CANCELLED`, releasing capacity without confirmation. Before the fix the new engine-driven assertion failed with actual `CANCELLED` versus expected `RECONCILIATION_REQUIRED`. The narrow fix adds that reconciliation state to the existing unconfirmed cancellation guard. The updated test verifies capacity remains held after both unconfirmed commands and releases only after a confirmed command. No authority path was added.

Both stock tests pass with Node 22.23.2 under `isolated-exec.py`, including two real SQLite connections competing for three units with two-unit requests. Run from the nested `backend` directory so worker `tsx/cjs` resolution uses its installed dependencies; a prior repository-root invocation failed that module resolution, not the stock assertion. This evidence is candidate-only and does not close the full Work8 inventory, endurance, or provider examination obligations.

### Bounded resumable fulfilment followup

Independent review identified unbounded historical scanning. The collector now persists a derived-only cursor in `work8_fulfilment_scan`, processes at most 256 missions per cycle, verifies no more than 512 receipts / 1 MiB per mission and 32 orders per mission, and indexes intake/tracking once per history. Configuration has hard upper ceilings. A single SQLite transaction fences budget checks, history reads and cursor writes against concurrent canonical writers. Exceeding a limit yields BLOCKED coverage with no order health assertion; it does not truncate history and pretend verification succeeded.

The separate stable coverage probe reports NOT_COMPLETE while paginating, STALE for sweeps beyond three minutes, and BLOCKED for oversized missions. A receipt watermark prevents a new mission inserted behind the cursor from producing false complete coverage. Existing order incidents close only when that order is freshly examined; skipped orders receive no replacement healthy observations. A completed sweep reports coverage, not business health. Continuous new receipts or a sufficiently large mission count can keep coverage incomplete/stale; that limitation is explicit and does not authorize broader scan work or repair.

Seven targeted fulfilment/runtime tests pass under isolated Node 22, including persisted cursor reopening, skipped incident retention, hard history bound refusal, stale completed sweep, concurrent insertion behind cursor, and registered actual runtime detection. Strict fulfilment test compilation with unchecked indexing enabled passes. No canonical commerce receipts are written by the collector, and no provider or paid model operation is introduced.
