# Retained evidence discovery queue

Existing engineering recovered: `intelligence/pipeline.ts::discoverNext` performs bounded supplier follow-up (one catalogue product, then one detail variant) through the existing request-budgeted job queue. `intelligence/runtime.ts` already schedules acquisition and reconciliation. `CommerceWorker.screen` qualifies imported commerce missions. None is replaced. The new `RetainedDiscoveryWorker` fills the missing durable, parent-deduplicated source-completeness scan; it invokes the strict source projection and does not acquire data or create commerce missions.

`start(workspace)` snapshots at most 1,000 existing CJ catalogue/detail evidence IDs and digests for the current Asia/Singapore day. `tick(workspace, day, expectedFence, batchSize=4)` processes at most four saved sources, with a 100 new-parent/day ceiling and explicit remaining shortfall. `read` verifies durable receipt chain and checkpoint consistency. Subsequent ticks append previously unseen source IDs and envelope digests to the same-day checkpoint without changing earlier receipt snapshots. SOURCE_EXHAUSTED is resumable when new evidence arrives. The 1,000-source/day bound and truncation remain explicit; this scan cannot claim full supplier coverage or sustained fresh-provider throughput. See fresh-acquisition.md for the separate bounded acquisition planner.

The existing IntelligenceStore `objects` table persists checkpoint, immutable-by-writer receipts and unique parent identities under separate `work8_discovery_*` kinds. `BEGIN IMMEDIATE` atomically commits identities, receipt and cursor. Duplicate concurrent calls for the same fence return the same persisted receipt. Independent processes test actual close/reopen/restart behavior. Source identity deduplication survives days, so a reread is not reported as a new parent. Stale/changed/invalid sources are quarantined. Every admitted observation remains DEFERRED for rights, eligibility, economics and genuinely completed Pillow assessment; counts for qualifications, assessments and recommendations stay zero.

Classification is `RETAINED_AUTHENTIC_EVIDENCE_SCAN`, not new provider discovery. The authentic retained cohort yields ten newly catalogued parent identities for an empty scan store and a 90/100 shortfall, with zero refresh, paid inference, publication or order effects. Freshness is rechecked at processing time, not copied from enqueue.

Candidate integration now invokes the retained worker through existing runtime ticks, including exhausted scans when new sources arrive. The existing intelligence scheduler also invokes a separate bounded acquisition planner described in fresh-acquisition.md. No additional timer or production registration is installed. Owner readback exposes retained scan and acquisition status separately. Production release remains separately gated. This does not connect unqualified observations to Pillow commissioning or autoapprove steps.

Tests cover two actual concurrent child processes, reopened process continuation, duplicate source identity, authentic under-supply, day rollover, expiry after enqueue, a 100-parent bound, receipt/checkpoint corruption, and injected SQLite receipt-commit failure with rollback. These are bounded isolated exams, not proof of full daily discovery, commerce integration, qualification or Work 8 completion.

## Independent review hardening

The source snapshot now binds both `facts` digest and the complete saved Evidence envelope digest. Changing expiry, observation time, authenticity, subject or other metadata after enqueue quarantines the source even when its facts hash stays identical. Receipts record both digests.

Every new parent identity is digest-bound to its committed tick receipt. Before start, read and mutation, the worker verifies all receipt chains, daily checkpoint heads and the identity index against those bindings. Deleted, edited or injected identities stop the scan with `DISCOVERY_IDENTITY_LINEAGE_CORRUPT`; they cannot silently cause rediscovery across days. Verification is repeated inside the mutation transaction. An explicit 10,000-receipt history verification bound stops safely for reviewed archival/index scaling; nothing is pruned or skipped. This is a deployment capacity limit, not a claim of unlimited daily operation.
